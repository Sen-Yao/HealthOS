# HealthOS 0.10.0

This release combines the persistent-session reliability update and training
entry improvements. It supersedes Docker Hub 0.9.9. The SQLite schema remains
compatible with the previous production image.

## Behavior

- New sign-ins use a Secure/HttpOnly/SameSite=Lax v2 cookie with a fixed browser
  deadline. Server authorization still expires after seven idle days or thirty
  absolute days. Existing legacy sessions continue without forced re-login.
- Login-page recovery, duplicate-submit prevention, stale authentication-result
  handling and credential-free cross-tab notification preserve active drafts.
- Authentication decisions are structured JSON, with credential and URL-query
  redaction. Rollback uses the captured image ID, not a movable latest tag.
- Set menus support delete/undo and group-type changes. Deleting the last group
  removes its exercise card. New groups inherit only the prior main weight.
- Exercise suggestions omit already selected canonical exercises/aliases while
  allowing manual duplicates. Save feedback separates local drafts from server
  acknowledgement and preserves edits across uncertain-write confirmation.

## Verification and release identity

The release gate passed all 53 Python tests, thirteen authentication browser
scenarios, eighteen desktop/mobile training scenarios and five disposable Docker
build/container-recreation smoke groups. The shell
rollback regression simulates both startup and health-check failure without production access.
Commands and prerequisites are in the root LOCAL_RUN.md.

Only source, repeatable tests and these notes belong in Git. Test screenshots,
logs, temporary certificates, probe scripts and source snapshots stay out of Git
and Docker build contexts. Release images carry the version, Git revision and
source URL as OCI labels. Docker Hub keeps immutable version tags and latest;
production is deployed by an explicitly verified release reference.

No production health-record writes are needed for acceptance.
A rollback to a pre-v2 release can require new
sign-in for users who obtained a v2 cookie. Real iOS Safari remains unverified.

concise acceptance JSON, test logs and current browser screenshots remain in
local ignored output for review. The unrelated pre-existing local development
